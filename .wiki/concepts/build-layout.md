# Build Layout

This page answers a simple question: which files do developers edit, and which files do users actually run?

## Source Trees

- `cli/src` is the command-line source.
- `core` is shared TypeScript source for runtime, config, prompts, storage, and workspace setup.
- `electron` is the local desktop shell.
- `tests` contains unit and live-provider E2E coverage.

The old `server/`, `web/`, and `agent-world-cli` surfaces are deleted.

## Shipped Outputs

- `bin/agent-cli.js` is the generated CLI executable.
- `electron/dist/main.js` is generated by `npm run electron:build`.

`core` remains TypeScript source checked with no emit. Generated runtime files beside `core/*.ts` are not the source of truth.

## Main Commands

- `npm run build` checks core and builds the CLI bundle.
- `npm run check` builds and runs `node --check` against key JS/test files.
- `npm run test:unit` builds and runs Vitest unit tests.
- `npm run test:e2e` builds and runs the local `agent-cli` live-provider E2E test.
- `npm run electron:build` builds the Electron main process.

## Why The Layout Matters

The repo used to publish several products. The current build layout makes the boundary harder to misunderstand: edit TypeScript sources, ship one CLI bundle, and keep Electron as a separate desktop build. Runtime behavior is [[cli-entry-and-host-modes]] and [[electron-shell]].
